- Git remote `origin` is the private repository `https://github.com/yashrathi/recipeapp.git`; verified `main` was first pushed on 2026-08-30.
- The user explicitly authorized the complete Milestone 1 build and later authorized Milestone 2 implementation, integration, push, and deployment on 2026-08-30. Milestones 1 and 2 are integrated and locally verified; do not infer approval for later product milestones.
- Swiggy cart, pricing, checkout, or delivery-tracking access is not known. Validate official partner/API access before committing scope or architecture.
- Preserve source attribution, extraction evidence, and per-field uncertainty. Never fabricate a recipe when a transcript or page cannot be processed.
- Separate canonical recipe versions from cooking-session progress and translations.
- The househelp experience is audio-first and must not require reading. Every activated control speaks its label; each new ingredient or step speaks automatically.
- Spoken language is chosen through audio samples during setup and can be changed from every househelp screen.
- Design first-time setup around one obvious initial tap before speech, because web audio behavior can vary by device/browser.
- Househelp screens use one verified focal visual at a time. Audio remains authoritative; visuals confirm meaning and never replace it.
- Use attributed official YouTube playback at a timestamp rather than downloading or repackaging step clips.
- Accessibility references checked 2026-08-30: [W3C Audio Control](https://www.w3.org/WAI/WCAG22/Understanding/audio-control) recommends user-initiated audio and requires a stop/pause or independent volume mechanism for longer automatic audio; [W3C Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) requires equivalent alternatives for meaningful visuals.
- YouTube policy reference checked 2026-08-30: [YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies-guide) require the standard attributed playback experience and prohibit downloading or separating video/audio outside supported behavior.
- Milestone 1 runtime is Node 24 with Next.js 16.3.3/React 19.2.8. Read the generated Next guidance in `AGENTS.md` and relevant local docs under `node_modules/next/dist/docs/` before changing framework code.
- SQLite/Drizzle and signed demo role sessions are local foundation choices, not approved production datastore/identity decisions. Production demo auth is disabled.
- Extracted quantities are stored as validated lossless JSON; legacy nullable numeric columns exist only for forward local migration compatibility and are not authoritative.
- The import API returns a persisted import envelope; homeowner consumers must unwrap its `data` member instead of assuming the draft is the top-level response.
- Node 24 may invoke a custom HTTP `lookup` callback with `options.all=true`; pinned-address transports must return an address array for that shape or Node raises `ERR_INVALID_IP_ADDRESS`.
- Firecrawl standard paid plans may reject `zeroDataRetention:true` with `403`. Always disable provider caching, make ZDR explicit opt-in for capable accounts, and never silently retry without ZDR after a rejected ZDR request.
- Firecrawl YouTube transcript markdown may omit timestamps or language. Preserve only supplied metadata, never synthesize timestamps, and fail to manual entry when a usable transcript is absent.
- Live Firecrawl-to-OpenAI YouTube import currently takes roughly 42–52 seconds. OpenAI extraction is bounded at 60 seconds; production request ceilings need additional headroom or a later background-job design.
- Homeowner authoring is English-first. Publication requires complete reviewed English speech and generates any missing Hindi dish, ingredient, and step guidance before finalizing; assignment similarly translates an English-only note. Hindi inputs are optional overrides. Assignment still atomically pins both locale snapshots, the published recipe version, spoken-content identity, and eligible bundled visual metadata.
- Househelp progress mutations are assignment-scoped and idempotent. A bounded local queue retries connectivity failures; rejected `409` mutations are retained for recovery rather than silently treated as success. A five-second stalled request guard releases the UI without allowing stale responses to overwrite current state.
- The househelp cooking menu combines active assignments with the household's current published recipes. Draft, archived, and incompletely reviewed recipes stay hidden. `Cook now` creates an ad-hoc cooking run with pinned English/Hindi snapshots; repeated starts resume the same active ad-hoc run. The menu presents one item at a time and hides a locally completed assignment while its offline completion is waiting to sync.
- Househelp language confirmation is a device preference, not an assignment screen. Reuse it when opening or resuming any dish and after `Done`; only the explicit language control should reopen selection.
- Househelp escape navigation must not depend indefinitely on speech or sync. `Cooking menu` stays explicitly available in the active task and completion views; `Done` also has a bounded automatic return. Reviewing an earlier cooking step is local-only and must not create a backward or duplicate progress mutation.
- Local Playwright runs use one worker because desktop and mobile projects share deterministic SQLite state. They use a dedicated per-run database and port `3100`; never reuse the normal development server/database for browser acceptance tests.
- The public preview is `ghormai.everythingweb.in` on SSH target `linode`: Caddy proxies to PM2 app `ghormai` on port `3021`, releases live under `/opt/ghormai/releases`, `/opt/ghormai/current` is the active symlink, runtime configuration is `/etc/ghormai/ghormai.env`, and the persistent SQLite file is `/var/lib/ghormai/recipe-app.sqlite`.
- macOS release archives can add `._*` AppleDouble sidecars that match the migration runner's `.sql` suffix filter. Build release archives with `COPYFILE_DISABLE=1` or equivalent, prove no `._*` files exist before migration, and clean only exact deployment-generated sidecars/rows if detected.
- Never build or replace `.next` inside the active/final release. Build in a unique `/opt/ghormai/incomplete` directory, atomically rename the whole completed release, coordinate a single deployment owner, then restart PM2 and verify its `/proc/<pid>/cwd` is the final release path.
